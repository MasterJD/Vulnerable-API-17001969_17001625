## 1. Overview

This pipeline enforces two governance gates on every commit and pull request:

| Gate | Tool | Threshold | Behavior |
|------|------|-----------|----------|
| **Code Complexity** | ESLint | Max cyclomatic complexity = 10 | Build fails if any function exceeds 10 independent code paths |
| **Code Coverage** | Jest | 80% minimum (branches, functions, lines, statements) | Build fails if any coverage metric drops below 80% |

Both gates run automatically in GitHub Actions and can be run locally with `npm run ci`.

## 5. How the Governance Gates Work

### Gate 1: Cyclomatic Complexity (ESLint)

```
Developer writes function with 12 decision points
  → npm run lint
  → ESLint reports: "Function has a complexity of 12. Maximum allowed is 10."
  → Exit code 1
  → CI build FAILS
  → Developer must refactor to reduce complexity
```

### Gate 2: Coverage Threshold (Jest)

```
Developer adds new code without tests → coverage drops to 75%
  → npm test
  → Jest reports: "Global coverage threshold for lines (80%) not met: 75%"
  → Exit code 1
  → CI build FAILS
  → Developer must add tests to restore coverage ≥ 80%
```

### Combined Flow in GitHub Actions

```
Push to any branch
  │
  ├─ Checkout + Setup Node
  ├─ npm ci (install from lock file)
  ├─ npm run lint ───── ESLint complexity check
  │     └─ FAIL? → Job fails immediately
  ├─ npm test ──────── Jest with coverage
  │     └─ FAIL? → Job fails immediately
  ├─ npm run report ── Generate governance reports
  └─ Upload artifacts (coverage + reports)
```
